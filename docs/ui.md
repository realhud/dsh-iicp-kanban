# dsh-iicp-kanban 界面设计（ui）

> v0.3（2026-11-18）：成员视图重写为「团队视图」——队长卡片 + 待验收队列 + 工作成员卡片网格 + 全员明细弹窗；成员弹窗新增成员类型/队长/人格/技能/提供方/模型/状态七个字段。
>
> 视觉（v0.4，2026-11-18）：全站切换为「深空 HUD」主题——深海军蓝网格底、青色全息描边与辉光、状态色（工作中绿 / 空闲黄 / 受阻粉）。看板列与任务卡、项目卡、团队视图、任务抽屉及弹窗共用同一套 token；状态文案统一为「空闲 / 工作中 / 受阻中」。

## 布局

插件通过 `ctx.slots.inject("main", …)` 占据 DSH 主区域，根元素 `div.iicp-board`（带 `data-plugin="iicp-kanban"` 标记，冒烟验证用）。纵向：页头（固定）+ 视图区（滚动）。

## 深空 HUD 主题（v0.4）

- **作用域**：`.iicp-board` 全局；三个视图、任务抽屉和所有弹窗共享同一套深色玻璃与青色描边。
- **色彩 token**：`--iicp-hud-cyan`（主色）/ `--iicp-hud-blue` / `--iicp-hud-green`（工作中）/ `--iicp-hud-yellow`（空闲、置顶、阻塞提示）/ `--iicp-hud-pink`（受阻、删除）；覆盖基础 `--iicp-ink`、`--iicp-surface`、`--iicp-line*`、`--iicp-accent`。
- **背景与页头**：深海军蓝 + 多层径向辉光 + 48px HUD 网格；标题白色带青色光晕；按钮为深色玻璃胶囊，主按钮青蓝渐变 + 深色文字。
- **看板**：列是深色玻璃面板，顶部有亮线，列头按待办灰蓝 / 进行中青 / 受阻粉 / 已完成绿着色；任务卡顶部亮线 + 左侧状态条，hover 轻微上浮，置顶卡黄色描边。
- **项目 / 抽屉 / 弹窗**：项目卡、任务抽屉、任务/项目/成员弹窗、筛选浮层、更多菜单和 toast 统一为深色玻璃 + 青色描边；项目进度条为青蓝渐变，逾期与删除保留粉色语义。
- **响应式**：`≤980px` 隐藏 `KANBAN · LIVE` / `PROJECTS · MATRIX` 装饰字；`≤760px` 看板列改为 236px 横向滚动（折叠列 64px）。

## 看板视图（默认）

- 四列 flex 布局：待办 / 进行中 / 受阻 / 已完成；列头为青色下边线 + 12px/600 标题 + 圆角计数 chip + 右侧 hover 才显现的「折叠」（仅已完成列）与「+」（在该状态新建任务）。
- 排序 `compareTasks`：置顶优先 → 优先级 P0…P3 → `updatedAt` 降序。
- 列内分页 30 条（`COLUMN_PAGE_SIZE`），超出时底部 `.iicp-pager` 显示「起始–结束 / 总数」与上一页/下一页。
- 列空时显示「暂无任务，拖拽卡片到这里」（受阻列「暂无受阻任务」）。
- 拖拽：卡片 `draggable`，目标列头下边线变深 + 列体 1px outline，drop 后乐观更新并 POST `/task.move`，成功 toast「已移动到「X」」，失败回滚 + 「移动失败：…」。
- **卡片（v2.3/v2.5，对齐 dsh-super-kanban v3）**：结构自上而下为
  1. 卡片头：6px 状态圆点（待办灰蓝 / 进行中青 / 受阻粉 / 已完成绿，`margin-top:6px`）+ 标题按钮 `.iicp-card-open`（13px/600，两行截断）+ 徽章组：`置顶`（`.iicp-mark`）、`已归档`、`AI`（`.iicp-ai-mark`，来自会话的任务）+ 右侧 hover 才显现的「更多」按钮（`.iicp-card-menu`）。
  2. 元信息行（11px，45% 墨色，flex 换行）：项目名或「未归属」+ `·` + 相对时间（刚刚 / N 分钟前 / N 小时前 / N 天前 / M/D）；右侧 `margin-left:auto` 指标组：优先级（P0 红 / P1 橙 / P2·P3 弱化）、`👤 成员名`（未指派不显示）、`📎 N`（交付物数，>0 才显示）、`✓ 已完成/总数`（子任务计数，全完绿色）。
  3. 计划行：`📅 MM-DD` 到期日（逾期未完成显示「已逾期 ·」+ 红色加粗）+ `#标签`。
  4. 摘要行（2 行截断）：有验收标准显示验收标准，否则显示目标文本。
  5. 进度条：3px 高 / 1.5px 圆角细条，进行中青色 75%、受阻粉色 75%、其余 20% 墨色；v0.4 使用青蓝渐变并带辉光。已完成任务的卡片不显示指标组与进度条，标题降为 500 字重；归档卡片整体 65% 不透明度。
  单击卡片打开详情抽屉（v2.4），双击打开编辑弹窗；Enter/Space 打开详情，焦点落在 `.iicp-card-open`。
- **卡片更多菜单**（`.iicp-menu`，fixed 定位，z-index 99）：查看详情 / 置顶任务（或取消置顶）/ 归档任务（或恢复）/ 移至「待办」「进行中」「受阻」「已完成」（当前状态不列）/ 删除任务（红色）。操作结果 toast 提示，Esc 或外部点击关闭。

## 团队视图（v0.3，原「成员视图」；深空 HUD 主题）

视图切换里的第三段文案为「团队」（key 仍是 `members`）。一次纵向呈现「一个队长带若干工作成员」：

1. **三栏指挥区**（`.iicp-team-hero`，`≥841px` 为 任务总监 / 队长 / 团队总览 三栏，列宽比例约 `.82fr / 1.55fr / .86fr`）：
   - **任务总监**（`.iicp-team-taskview`，左侧）：`TASK STATUS` + 「任务总监」+ 四行状态点指标（**待验收 / 进行中 / 受阻 / 未指派**），底部 `TASK FLOW` 展示四列任务占比条、完成百分比、任务总数与已完成数。
   - **队长**（`.iicp-team-hero-main`，中间）：先显示 `.iicp-team-hero-heading`（青色竖条 + 「队长」+「做的人不验收」+ `TEAM LEAD` kicker），下面是 `.iicp-team-lead` 发光全息卡：64px 渐变头像（首字，带呼吸光）、22px 名字、职位 `·` 模型、状态胶囊 + `♛ N 门下`（`.iicp-team-lead-tags` 单独一行）；再往下是人格（`.iicp-team-bio`，2 行截断）、技能 chips（`.iicp-team-skill`）、原任务指标位置的「新增成员」按钮（`.iicp-team-lead-add`，26px 常规尺寸，不再全宽拉伸）和底部「编辑」。队长卡不再承载任务指标。
   - **团队总览**（`.iicp-team-squad`，右侧）：`SQUAD STATUS` + 「团队总览」标题行（右侧 `.iicp-team-roster-link`「全部成员 N」按钮）+ 四行勾选指标（工作成员 / 进行中 / 待验收 / 受阻）+ CSS 雷达（双环、十字准星、队长首字核心，最多 3 个成员节点）。
   - `≤840px` 时三栏按「队长 → 任务总监 → 团队总览」纵向堆叠，任务总监指标改为两列。
2. **待验收队列**（`.iicp-team-reviews` / `.iicp-review-list`，仅当有 `pendingReviews` 时出现）：琥珀左边条 + 每行标题 + 提交人 + 相对时间 + 提交说明，右侧「验收」按钮打开验收弹窗。整段空时不渲染，队列处理完后不再占位。
3. **工作成员卡片网格**（`.iicp-team-grid`，宽屏固定 4 列，`≤900px` 两列）：上方 `.iicp-team-branch` 用发光竖线 + 横线 + 四个分叉把队长区连到卡片（`≤900px` 隐藏）；卡片为深色玻璃 + 状态色描边（工作中绿 / 受阻粉 / 无队长琥珀），头部 44px 渐变头像（带状态点）、名字 + 职位 `·` 提供方/模型、状态胶囊（空闲黄 / 工作中绿 / 受阻粉 / 待验收粉）；下面是技能 chips、三格指标 `任务数 · 进行中 · 受阻`，底部操作 `派单` + `编辑`。`leadId` 为空时标注「队长已卸任」。
4. **orphan 提示条**（`.iicp-team-banner`）：存在无队长成员时显示「这些成员暂时没有队长…」，说明新队长上任会自动接管。
5. **全员明细弹窗**（`.iicp-roster-modal`）：由团队总览右上角「全部成员 N」按钮打开。弹窗标题带成员总数，内部 `.iicp-roster-scroll` 横向滚动、`.iicp-roster-table` 最小宽度 760px，保留 7 列表格：名称（带 `队长`/`工作成员` 小标签）| 角色 | 成员状态 | 队长 | 职位 | 任务 | 操作（编辑 / 删除，删除仍需 `window.confirm`）。点击编辑会先关闭明细弹窗再打开成员弹窗；弹窗底部「关闭」，点击遮罩也可关闭。

- 状态文案与配色：**空闲（黄）/ 工作中（绿）/ 受阻中（粉）**；有 `awaitingReview` 的成员卡优先显示粉色「待验收 N」。
- 视觉实现：基础 HUD 主题作用于 `.iicp-board` 全局，团队专属规则只匹配 `.iicp-team-*`；`.iicp-team-view` 给团队 slimbar 加 `SQUAD · ONLINE` 装饰。看板/项目视图共享同一套 HUD token，不再是 DSH 原生单色。

- 空态：一个成员都没有时显示引导「团队里还没有成员…」；服务端 `team` 聚合缺失时前端用本地 `members.find(kind==="lead")` 兜底，不会白屏。
- **派单弹窗**（`DispatchModal`）：列出未归档、未指派、未完成的候选任务，选中后 POST `/member.dispatch`，成功 toast「已派单」。
- **验收弹窗**（`ReviewModal`）：textarea 预填提交说明，两个动作按钮「要求返工」（`decision:"changes"`）/「通过并标为完成」（`decision:"accepted"`），带当前 lead 的 `leadId`。
- 文案「做的人不验收」直接写在视图里，让队长知道提交与验收是两回事。

## 项目视图（v2.6）

卡片网格（`auto-fill minmax(min(100%,268px),1fr)`），分三段：

1. **引导文案**：「工作区来自 DSH 的工作目录，会自动出现；自建项目由你创建，可以把不同工作区的任务归到一起。」
2. **工作区项目**（副标题「按 DSH 工作区自动生成」）：每张卡片 = 名称 + 指标行（`近期 done/total 已完成 · N 项受阻 · N 项逾期 · N 项进行中`，无任务时「暂无近期任务」）+ 进度条（`role="progressbar"`）+ 「看板」按钮。
3. **自建项目**（副标题「手动创建，可跨工作区」）：卡片额外带到期日（逾期红字「已逾期 · 日期」）、备注、`看板 / 编辑 / 归档 / 删除`（删除为红色 danger）。空态：「还没有自建项目。点右上角「新建项目」把一个或多个工作区的任务归到一起。」
4. **已归档项目（N）**：`<details>` 折叠；归档卡片 70% 不透明度，按钮变为 `看板 / 编辑 / 恢复 / 删除`。

点任意卡片的「看板」会切回看板视图并带入范围：自建项目 → 选中该「项目」下拉，过滤计数角标 +1；工作区卡片 → 选中「工作区」下拉（任务自身 workspaceId 命中，或任务归属绑定该工作区项目的，二者之一即显示）。

- **v0.4 视觉**：项目卡为深色玻璃 + 顶部亮线，进度条青蓝渐变；到期/逾期用黄/粉语义，已归档卡片降低不透明度。

**v2.7 约束**：同一工作区只能有一个未归档项目。给项目选一个已被占用的工作区并保存，会收到 409 与提示文案；归档该项目即让出绑定。删除项目后，原属任务的历史里会新增一条「项目已删除，任务改为无项目（原项目：X）」，卡片相对时间也会刷新。

## 弹窗

统一的 `Modal`：全屏半透明遮罩（点击遮罩空白处关闭）+ 居中卡片（520px/16px 圆角）+ 标题 + 内部滚动 body + 底部 `[取消][保存]`。v0.4 起弹窗为深空 HUD 深色玻璃 + 青色描边，输入框/下拉/分段按钮统一深色，`color-scheme: dark` 让原生控件与日期选择器不再闪白。

| 弹窗 | 字段 |
| --- | --- |
| 任务 | 标题(80，placeholder「要做什么？」，Enter 直接提交) / 目标(280,textarea，可选+引导 placeholder) / **验收标准(600,textarea，可选，v2)** / **折叠区「项目、到期日与备注」**：**指派给+到期日并排一行（v2.2 两列）**/ 项目 / 标签 / 备注(280,textarea) / **状态+优先级并排一行（v2.2 两列，seg 按钮组 flex:1 等宽自适应）** / **子任务列表（勾选完成、×删除、+添加 ≤60 字，v2）** / **交付物列表（📎 名称+×删除+路径添加 ≤260 字，v2）** |
| 成员 | 名称(40，autoFocus) / **[成员类型 + 角色] 双列**（`队长` \| `工作成员` + 负责人/管理员/成员/访客）/ **队长 select（仅 worker 且存在其他队长时出现）** / **[职位 + 成员状态] 双列** / 人格(200,textarea,rows=2，placeholder「这个成员擅长什么、验收要盯什么」) / 技能(逗号分隔，最多 8 个) / **[提供方 + 模型] 双列 select（v0.4：首项「继承工作区」，选项来自宿主模型目录，下方一行 `.iicp-team-hint` 提示）** / 联系方式(80) |
| 项目 | 名称(80，placeholder「要给这个项目起个名字」，Enter 提交) / 备注(600,textarea，placeholder「这个项目要解决什么问题、验收标准是什么」) / **到期日+关联工作区并排一行（v2.6 两列）** / 编辑态额外「归档」checkbox（文案「归档后默认不在列表显示」） |

- **项目弹窗的失效绑定提示（v2.7）**：`workspaceId` 不在当前工作区选项里时（历史脏值），下拉会多出一项「`<id>`（已失效）」并保持选中，下方提示「该工作区已不在 DSH 中，保存后会解除绑定」，避免静默显示成「不关联工作区」。
- **成员弹窗的模型选择（v0.4）**：提供方/模型改为 `<select>`，选项来自 `GET /models`（宿主 `llm` 服务的真实目录，打开弹窗时取一次）。
  - 首项固定为空值「继承工作区」；选中时下方提示「跟随工作区默认模型 · provider/model」，把宿主的当前默认模型摊开给用户看。
  - `provider` 已不在目录里时，下拉 unshift 一条「`<id>`（当前值不在目录里）」并保持选中——历史值可以看不懂，但不能被静默改掉。
  - 换 provider 时模型的处理：仍属于新 provider 就保留；否则优先该 provider 的宿主默认模型；再没有就取首个模型。只选模型而 provider 为空时，自动补上归属 provider，避免存下无法路由的 model。
  - 目录不可用（`available:false`，如 `llm` 服务未就绪）时两块退回普通 `<input maxLength=60>`，下方提示「模型目录不可用可手填」——表单不能因为宿主服务缺席而无法保存。
  - 该 provider 在目录里没有任何模型时提示「该提供方没有可用模型」；读取中提示「正在读取模型目录」。
- **团队卡片的模型副标题（v0.4）**：队长卡与工作成员卡副标题走同一个 `memberModelLabel()`：有值显示 `provider/model`；都为空显示「继承工作区」；只有一半有值则显示那半个。这样「继承」和「从没配过」在界面上不再长得一样。
- **项目保存的冲突反馈（v2.7）**：编辑走 `expectedUpdatedAt: initial.updatedAt`；服务端 409 或唯一绑定 409 时 `window.alert("保存失败: …")` 并重新 `reload()`，让用户看到最新数据后再决定。
- **成员弹窗（v0.3）**：无队长时标题为「新建成员成为队长」，否则「新建成员」；成员类型默认 `工作成员`。与项目弹窗一样带 saving 态（「保存中…」）+ `try/catch` + `window.alert("保存失败: …")` + `reload()`。技能输入框按中英文逗号切分，服务端先去重再截到 8 个。

- 子任务行：checkbox（accent 色，`width:auto` 覆盖 `.iicp-field input` 的 `width:100%`）+ 文本（完成后划线弱化）+ 来源标记（ai/todo 小徽章，manual 不显示）+ × 删除；子任务被 `lockedFields` 锁定时显示「🔒 子任务已锁定」。
- 交付物行：`📎 文件名`（悬浮显示完整路径）+ × 删除；添加框输入路径回车或 + 确认。
- **v2.1 表单交互**（对齐 dsh-super-kanban NewTaskModal）：折叠区在编辑已有指派/项目/到期日/备注的任务时自动展开；状态与优先级为 seg 按钮组（aria-pressed，on 态弱背景）；保存按钮 saving 态显示「保存中…」并禁用重复提交，失败 `window.alert` 提示。
- **v2.3 卡片**：到期日以 `📅 MM-DD` 形式并入卡片计划行（不再用直角标签胶囊），逾期未完成整段变红加粗；优先级、指派给、交付物数、子任务计数统一收进右侧指标组。

## 任务详情抽屉（v2.4）

单击卡片从右侧滑出详情抽屉（`width:min(540px,94vw)`，`role="dialog"` + `aria-modal="true"`，挂 `data-drawer="task-detail"`）；双击卡片仍打开上面的编辑弹窗（原行为不变）。点击遮罩、左上返回按钮或 Esc 关闭。v0.4 起抽屉为深海军蓝渐变 + 左侧青色光边，遮罩带模糊，子任务/交付物/历史均使用 HUD 深色层级。

- **头部**：返回按钮 + 11px 青色 kicker「任务详情」+ 18px/600 两行截断标题。
- **任务概览**：状态点 + 状态名 + `·` + 优先级（P0 红/P1 琥珀）+ `·` + 进度 + `·` + 指派人；下面两列网格：目标（跨行）/ 验收标准（跨行）/ 指派给 / 项目 / 到期日（逾期红字）/ 标签 / 备注（跨行）。空值统一显示「暂无」。
- **子任务**：节头右侧 `done/total` 计数；每行为 15px 方框（完成时填实心并画勾）+ 文本（完成态弱化+删除线）+ `ai`/`todo` 来源徽章。
- **交付物**：节头计数 + 每行「文件名（悬浮显示完整路径）+ 路径弱化显示」。
- **变更历史**：倒序 `YYYY/MM/DD HH:mm` + 说明；底部「创建时间 / 更新时间」。
- **底部**：`[打开编辑]`（primary，关抽屉并打开编辑弹窗）+ `[关闭任务详情]`。
- 抽屉数据跟随 8 秒轮询刷新，任务被删除时自动关闭。
- **单击/双击区分**：自行计时 350ms 内的第二次点击判定为双击（合成点击不派发 `dblclick`，`event.detail` 也不可靠）；卡片为 `role="button" tabIndex=0`，Enter 打开详情。

## 加载与错误

- 首次加载：页头与 slimbar 可见，视图区显示 `.iicp-loading` 三行骨架（`iicpPulse` 呼吸动画，`aria-busy="true"`）；统计行显示「正在加载…」。
- 请求失败：`.iicp-empty-state` 显示「看板加载失败」+ 具体原因 + `[重试]` 按钮 + 小字「后台会自动重连，也可以稍等几秒。」；轮询持续重试。
- 操作反馈：`.iicp-toasts`（fixed 底部 24px 居中，z-index 1200，`pointer-events:none`）显示 2.6s 自动消失的 toast（置顶/归档/移动/删除成功与失败）。
- 语言：中文为源 key；`activeLanguage` 非 zh 开头时查 EN_MESSAGES 映射表，未命中回退中文 key。
- 样式注入：`<style id="iicp-kanban-style">`，v0.4 以 `--iicp-hud-*` 与覆盖后的 `--iicp-*` token 为主，基础色保留 DSH CSS 变量（`--dsw-alias-*`）回退值。

## 交互细节

- 成员/项目下拉过滤时用 `"__none__"` 表示「未指派/无项目」哨兵值，避免与真实 id 冲突。
- 键盘快捷键（v2.5）：`/` 聚焦搜索框；`n`/`N` 新建任务（项目视图下新建项目）；`Esc` 逐层关闭——筛选浮层 → 卡片菜单 → 编辑弹窗 → 详情抽屉 → 清空搜索；焦点在输入框内时只响应 `Esc`。
- 轮询 8s：`setInterval(reload, 8000)`，组件卸载清除。
- 刷新策略：非拖拽操作用服务端返回结果刷新；拖拽先乐观更新本地状态再请求，失败回滚并 toast。
