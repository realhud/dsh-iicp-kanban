# dsh-iicp-kanban 使用说明书（manual）

> 面向使用者。安装与日常操作。

## 这是什么

DSH 团队任务看板插件：在 DSH 界面里维护一张「待办 → 进行中 → 受阻 → 已完成」四列看板，支持**一个队长 Agent 带领多个工作 Agent**的团队协作（派单 / 提交 / 验收）、**任务指派**、**项目分组**，以及从 DSH 工作区列表自动发现工作区。单机本地数据，存放在 `$DSH_HOME/storages/iicp-kanban/state.json`。

## 安装

```powershell
# 在 DSH 配置中安装（link 方式，源码即时生效）
# package.json: name=dsh-iicp-kanban, main=./index.mjs
```

安装后重启 DSH，打开 DSH Web 界面，主区域出现「团队看板」面板即成功。健康检查：`GET /iicp-kanban/api/ping` 返回 `{"ok":true,"plugin":"dsh-iicp-kanban",...}`。

## 界面导览

页头右侧是搜索框与「新建」按钮；下方 slimbar（细分工具栏）最左边是三个视图切换按钮：

| 视图 | 功能 |
| --- | --- |
| **看板** | 四列任务卡片。拖拽卡片到另一列 = 改状态。slimbar：按项目、按指派成员过滤，「可见 / 总数」计数，右侧「筛选」浮层（优先级 / 来源 / 标签 / 含归档）。**单击卡片看详情、双击卡片编辑**。右上「搜索任务」+「新建任务」。 |
| **项目** | 卡片网格分三段：「工作区项目」（按 DSH 工作区自动生成，只读卡片）/「自建项目」（手动创建，可跨工作区）/「已归档项目（N）」折叠区。卡片显示指标行、进度条、到期日、备注，按钮 看板 / 编辑 / 归档（恢复）/ 删除。点「看板」会切回看板并按该项目或工作区过滤。 |
| **团队** | 你的一支队伍：**队长卡片**（头像、名字、职位/模型、`N 门下`、人格、技能、待验收/进行中/受阻/未指派四项指标）+ **待验收队列**（工人提交的活排队等你拍板）+ **工作成员卡片网格**（状态徽标、技能、任务数，可「派单」）+ **全员明细表**。可新建/编辑/删除成员。删除成员后其任务自动变为「未指派」，并在任务历史里记录原成员名。 |

### 团队怎么用（v0.3）

1. **第一个成员自动成为队长**。之后新建的成员默认是「工作成员」，自动挂在现任队长名下。想换队长：把原队长的成员类型改成「工作成员」（卸任），再把目标成员改成「队长」——卸任不会删任何人、也不会解绑任务。
2. **派单**：在工作成员卡片上点「派单」，选一个还没人认领的任务。任务从「待办」进入「进行中」，历史里写「派单：X 认领」。
3. **提交**：工作成员干完后提交（一句说明 + 可附子任务/交付物勾选）。**任务不会自己变「已完成」**——提交只是把它挂进「待验收」。
4. **验收**：队长在待验收队列里点「验收」，选「通过并标为完成」（任务进已完成、AI 子任务自动关闭）或「要求返工」（任务退回进行中并记下要改什么）。**做的人不能验收自己的活**，服务端会挡住。
5. 你也可以直接在看板把某人的任务拖到「已完成」，这视为你已经验收过了，系统会补记「人工直接完成（视同验收）」。

> 队长带工人只是本地看板里的协作规则，**不会真的去启动 AI 会话**（成员上的「提供方/模型」是画像字段，见文末「已知边界」）。

## 常用操作

- **新建任务**：页头右上「新建任务」（或按 `n`，或点列头 `+` 直接在那一列建）。填标题（必填，≤80 字，输入框占位「要做什么？」，回车可直接提交）、目标、**验收标准**（≤600 字）、优先级 P0–P3、状态；指派给/项目/**到期日**/标签/备注收在折叠区「项目、到期日与备注」里（编辑已填这些字段的任务时自动展开）。
- **到期日**（v2.1）：任务弹窗折叠区内选择日期（YYYY-MM-DD）。卡片显示 📅 日期；**过期未完成**（日期早于今天且状态不是已完成）时日期显示红色，提醒逾期。
- **搜索与筛选**（v2.5）：页头搜索框按标题、验收标准、目标、标签实时过滤（按 `/` 聚焦）；「筛选」浮层可按优先级（P0–P3）、来源（手动 / AI）、标签过滤，并可勾选「含归档」查看归档任务；「清空筛选」一键复位。slimbar 的「可见 / 总数」实时反映过滤结果。
- **卡片更多菜单**（v2.5）：悬停卡片右上出现 `…`，菜单含 查看详情 / **置顶任务**（或取消置顶）/ **归档任务**（或恢复）/ 移至「待办」「进行中」「受阻」「已完成」/ 删除任务。置顶任务排在列内最前并显示「置顶」徽章；归档任务默认隐藏，需在筛选浮层勾「含归档」才显示。
- **子任务**：任务弹窗内可添加子任务（≤12 项，每项 ≤60 字）、勾选完成、删除。有子任务时卡片显示进度条与「已完成/总数」计数——进度自动推导，无需手填。
- **交付物**：任务弹窗内可登记产出文件路径（≤10 项），卡片显示 📎 计数。AI/agent 会话产生的任务会自动带上目标、子任务与交付物。
- **看任务详情**（v2.4）：**单击**任意卡片，右侧滑出详情抽屉——任务概览（状态/优先级/进度/指派人 + 目标、验收标准、项目、到期日、标签、备注）、子任务勾选状态、交付物路径、变更历史与创建/更新时间。抽屉底部「打开编辑」可直接转到编辑弹窗；点遮罩、左上返回或按 Esc 关闭。**双击**卡片仍是原来的编辑弹窗。
- **拖拽改状态**：按住卡片拖到目标列松手。移动即时生效并弹出「已移动到「X」」提示，失败会回滚并提示原因。状态变更写入任务历史；**拖到「已完成」时**：目标状态自动变为已完成、未完成的 AI 生成子任务自动关闭（人工添加的子任务保留）、进度重算。
- **指派/改派**：编辑任务时在「指派给」下拉选择成员；也可选「未指派」。每次改派写历史（原成员 → 新成员）。
- **列表过长**：单列超过 30 张卡片时分页，列底显示「起始–结束 / 总数」与上一页/下一页；已完成列可点列头「⌃」折叠。
- **键盘**：`/` 聚焦搜索、`n` 新建、`Esc` 逐层关闭（筛选浮层 → 卡片菜单 → 编辑弹窗 → 详情抽屉 → 清空搜索）。
- **新建/管理项目**（v2.6）：页头右上「新建项目」填名称（≤80，必填）、备注（≤600）、**到期日**、**关联工作区**（可留空=不关联）；编辑弹窗可勾「归档」把项目收进「已归档项目」。卡片指标行会滚动显示 `近期 done/total 已完成`、`N 项受阻`、`N 项逾期`、`N 项进行中`（无任务时显示「暂无近期任务」）。归档项目**不能再接收新任务**；删除项目会确认，项目内任务保留但变为「无项目」。
- **从项目跳到看板**（v2.6）：点任意项目卡片的「看板」→ 切回看板视图并自动带入范围（自建项目选中该「项目」下拉；工作区卡片选中该「工作区」下拉），计数与筛选角标同步变化。
- **工作区绑定规则**（v2.7）：一个工作区同时只能绑定**一个未归档项目**——想给新项目绑已被占用的工作区，会提示冲突；先把旧项目归档（归档即让出绑定）或改其绑定即可。归档项目删除后，原属任务的历史里会出现「项目已删除，任务改为无项目（原项目：X）」，方便回溯。
- **多窗口编辑**（v2.7）：项目编辑带乐观锁。若同一项目在另一个窗口被改过，你这边保存时会提示「项目已被其他窗口修改」，弹窗内容会按最新数据刷新，确认后重存即可，不会静默覆盖。
- **新建/编辑成员**（v0.3）：页头右上「新建成员」。字段：名称（≤40，必填）、成员类型（队长/工作成员）、角色（负责人/管理员/成员/访客，人类权限标签）、队长（工作成员可换归属）、职位、成员状态（待命/工作中/受阻中）、人格（≤200，写这个成员的行事准则）、技能（逗号分隔，最多 8 个）、提供方、模型、联系方式。**没有队长时，第一张成员卡片的标题会显示「新建成员成为队长」**。成员状态对工作成员通常由任务自动推导（有受阻任务→受阻中，有未完成任务→工作中），手工设置会被下一次刷新覆盖。
- **删除**：成员与项目删除前有确认框。任务在卡片菜单「删除任务」或编辑弹窗内删除。删掉队长不会连坐——工作成员留在队里、任务照旧归属，新队长上任时自动接管。

## 数据与安全

- 数据全部本地存储，不联网。
- API 仅 DSH **owner** 身份可用（`connection.admit` 判定，非 owner 一律 403）。
- 状态文件损坏时自动备份为 `state.json.corrupt-<时间戳>` 并以空状态重启，不会卡死插件。
- 项目绑定的工作区若已从 DSH 中移除（工作目录被删/改名），插件启动时会自动解除该绑定并记一条警告日志；这类历史遗留值过去会显示成「不关联工作区」，v2.7 起在编辑弹窗里明确标为「（已失效）」。

## 已知边界（v0.3）

- 单用户本地模型：成员是「指派与协作对象」，不参与鉴权，不能登录。
- **队长/工人规则是本地看板内的协作契约**：插件不注入 DSH 的 `agents`/`subagents` 服务，不会真的为成员拉起 AI 会话。成员上的 `provider` / `model` / `sessionId` 目前是画像与预留字段，改它们不会让某个 agent 开始干活。想做真实 spawn，需要额外接线（见 architecture.md「为什么不做真实 spawn」）。
- agent 写入任务数据走 `/iicp-kanban/api`（owner 凭证），本插件不主动拉取会话日志（与 super-kanban 的会话分析器不同）；`lockedFields` 为 agent 分析预留字段保护。工作成员可通过 `/member.report` 提交，队长通过 `/member.review` 验收，这条链路是纯 API 规则，任何持有 owner 凭证的调用方都能用。
- 工作区发现依赖于 `$DSH_HOME/storages/workspace.json`：该文件不可读时插件不会校验也不会清理工作区绑定（宁可保留未知值也不误删数据）。
- 与 super-kanban 的差距（v2.7 已补齐工作区唯一绑定与项目乐观锁）：仍未实现项目「时间线/日程」子视图、工作区范围/活动时间范围切换、多面板形态（侧边栏/浮窗）、导出 JSON、AI 扫描与快聊。
