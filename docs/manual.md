# dsh-iicp-kanban 使用说明书（manual）

> 面向使用者。安装与日常操作。

## 这是什么

DSH 一体化智能协作平台插件：在 DSH 界面里维护一张「待办 → 进行中 → 受阻 → 已完成」四列看板，支持**一个队长 Agent 带领多个工作 Agent**的团队协作（派单 / 提交 / 验收）、**任务指派**、**项目分组**、**任务前置依赖**，以及从 DSH 工作区列表自动发现工作区。单机本地数据，存放在 `$DSH_HOME/storages/iicp-kanban/state.json`。

## 安装

```powershell
# 在 DSH 配置中安装（link 方式，源码即时生效）
# package.json: name=dsh-iicp-kanban, main=./index.mjs
```

安装后重启 DSH，打开 DSH Web 界面，主区域出现「一体化智能协作平台」面板即成功。健康检查：`GET /iicp-kanban/api/ping` 返回 `{"ok":true,"plugin":"dsh-iicp-kanban",...}`。

## 界面导览

页头右侧是搜索框与「新建」按钮；下方 slimbar（细分工具栏）最左边是三个视图切换按钮：

| 视图 | 功能 |
| --- | --- |
| **看板** | 四列任务卡片。拖拽卡片到另一列 = 改状态。slimbar：按项目、按指派成员过滤，「可见 / 总数」计数，右侧「筛选」浮层（优先级 / 来源 / 标签 / 含归档）。**单击卡片看详情、双击卡片编辑**。右上「搜索任务」+「新建任务」。 |
| **项目** | 卡片网格分三段：「工作区项目」（按 DSH 工作区自动生成，只读卡片）/「自建项目」（手动创建，可跨工作区）/「已归档项目（N）」折叠区。卡片显示指标行、进度条、到期日、备注，按钮 看板 / 编辑 / 归档（恢复）/ 删除。点「看板」会切回看板并按该项目或工作区过滤。 |
| **团队** | 你的一支队伍：**队长卡片**（头像、名字、职位/模型、`N 门下`、人格、技能、待验收/进行中/受阻/未指派四项指标）+ **待验收队列**（工人提交的活排队等你拍板）+ **工作成员卡片网格**（状态徽标、技能、任务数，可「派单」）+ **全员明细表**。可新建/编辑成员、删除工作成员（队长不可删除）。删除成员后其任务自动变为「未指派」，并在任务历史里记录原成员名。 |

### 团队怎么用（v0.5：队长会话 + 真实 agent）

1. **队长恒在**：团队视图永远有一张队长卡片——首次使用时系统自动创建默认队长「队长」（可在卡片上点「编辑」改名、填人格与技能），之后新建的成员都是「工作成员」，自动挂到队长名下。**队长不可删除、也不可卸任**（服务端直接拒绝），换队长路径已关闭；想调整队长只改资料字段即可。
2. **开队长会话**：页头点「队长」打开右侧聊天抽屉。队长先给一份计划（建哪些卡、派给谁），你回复「确认执行」后它才建卡派单；不满意就直接说怎么改。抽屉里的回复是流式的，连接断开会自动退回轮询。
3. **派单即开工**：在工作成员卡片点「派单」，或让队长调用派单工具。任务进入「进行中」，插件会为该成员在该任务所属工作区拉起（或恢复）一个真实 agent 会话，并投递任务简报（标题、目标、验收标准、前置、工作区路径）。**同一工作区同一时刻只跑一个任务**，其余排队（成员徽标显示「排队中」）。
4. **成员汇报**：成员 agent 用 `report` 工具汇报进展 / 受阻 / 完成。**任务不会自己变「已完成」**——完成只是挂进「待验收」；受阻会立即唤醒队长。
5. **验收**：队长或你在待验收队列点「验收」，选「通过并标为完成」（任务进已完成、AI 子任务自动关闭）或「要求返工」（任务退回进行中，打回意见会补投给原成员并重新排队）。**做的人不能验收自己的活**。
6. **人工优先**：你可以随时拖卡、改派、直接拖到「已完成」（视同验收）；agent 的后续执行不会覆盖你的操作。前置未完成时，拖入「进行中」或派单仍会被 409 挡住。

> v0.5 起，队长与工作成员各自运行真实 DSH agent 会话：会话按「成员 × 工作区」映射，权限 `workspace-write`，插件只通过这些会话投递简报；任务状态的唯一事实仍在看板。宿主未提供 `agents` 服务时自动降级——任务照常排队、成员标「会话不可用」，你可以继续人工派单与汇报。

## 常用操作

- **新建任务**：页头右上「新建任务」（或按 `n`，或点列头 `+` 直接在那一列建）。填标题（必填，≤80 字，输入框占位「要做什么？」，回车可直接提交）、目标、**验收标准**（≤600 字）、优先级 P0–P3、状态；指派给/项目/**到期日**/标签/备注收在折叠区「项目、到期日与备注」里（编辑已填这些字段的任务时自动展开）。
- **到期日**（v2.1）：任务弹窗折叠区内选择日期（YYYY-MM-DD）。卡片显示 📅 日期；**过期未完成**（日期早于今天且状态不是已完成）时日期显示红色，提醒逾期。
- **搜索与筛选**（v2.5）：页头搜索框按标题、验收标准、目标、标签实时过滤（按 `/` 聚焦）；「筛选」浮层可按优先级（P0–P3）、来源（手动 / AI）、标签过滤，可勾选「仅看可开工」隐藏前置未完成的任务，并可勾选「含归档」查看归档任务；「清空筛选」一键复位。slimbar 的「可见 / 总数」实时反映过滤结果。
- **卡片更多菜单**（v2.5）：悬停卡片右上出现 `…`，菜单含 查看详情 / **置顶任务**（或取消置顶）/ **归档任务**（或恢复）/ 移至「待办」「进行中」「受阻」「已完成」/ 删除任务。置顶任务排在列内最前并显示「置顶」徽章；归档任务默认隐藏，需在筛选浮层勾「含归档」才显示。
- **子任务**：任务弹窗内可添加子任务（≤12 项，每项 ≤60 字）、勾选完成、删除。有子任务时卡片显示进度条与「已完成/总数」计数——进度自动推导，无需手填。
- **队长会话（未发布）**：页头「队长」打开聊天抽屉。队长先给计划，确认后批量建卡并派单；抽屉支持流式回复、Enter 发送、Shift+Enter 换行、断线轮询兜底。宿主未提供 agents 服务时抽屉显示不可用说明，其余功能不受影响。
- **前置任务（未发布）**：新建/编辑任务时在「前置任务」里选最多 8 张卡（可跨项目）。前置全部完成前，任务不能进入「进行中」——拖拽、编辑、派单都会被服务端挡住并提示还差哪几张；卡片显示「等待前置 N」，详情抽屉列出前置与各自状态。前置完成后不会自动开工，仍要你拖动或派单；前置被重开也不会把已开工的任务退回。删除前置任务会自动从依赖方摘除。
- **交付物**：任务弹窗内可登记产出文件路径（≤10 项），卡片显示 📎 计数。AI/agent 会话产生的任务会自动带上目标、子任务与交付物。
- **看任务详情**（v2.4）：**单击**任意卡片，右侧滑出详情抽屉——任务概览（状态/优先级/进度/指派人 + 目标、验收标准、项目、到期日、标签、备注）、前置任务（标题/状态/跨项目名）、子任务勾选状态、交付物路径、变更历史与创建/更新时间。抽屉底部「打开编辑」可直接转到编辑弹窗；点遮罩、左上返回或按 Esc 关闭。**双击**卡片仍是原来的编辑弹窗。
- **拖拽改状态**：按住卡片拖到目标列松手。移动即时生效并弹出「已移动到「X」」提示，失败会回滚并提示原因。拖入「进行中」时若前置未全部完成，请求会被 409 挡住，卡片回滚并提示还差哪几张。状态变更写入任务历史；**拖到「已完成」时**：目标状态自动变为已完成、未完成的 AI 生成子任务自动关闭（人工添加的子任务保留）、进度重算。
- **指派/改派**：编辑任务时在「指派给」下拉选择成员；也可选「未指派」。每次改派写历史（原成员 → 新成员）。
- **列表过长**：单列超过 30 张卡片时分页，列底显示「起始–结束 / 总数」与上一页/下一页；已完成列可点列头「⌃」折叠。
- **键盘**：`/` 聚焦搜索、`n` 新建、`Esc` 逐层关闭（筛选浮层 → 卡片菜单 → 编辑弹窗 → 详情抽屉 → 清空搜索）。
- **新建/管理项目**（v2.6）：页头右上「新建项目」填名称（≤80，必填）、备注（≤600）、**到期日**、**关联工作区**（可留空=不关联）；编辑弹窗可勾「归档」把项目收进「已归档项目」。卡片指标行会滚动显示 `近期 done/total 已完成`、`N 项受阻`、`N 项逾期`、`N 项进行中`（无任务时显示「暂无近期任务」）。归档项目**不能再接收新任务**；删除项目会确认，项目内任务保留但变为「无项目」。
- **从项目跳到看板**（v2.6）：点任意项目卡片的「看板」→ 切回看板视图并自动带入范围（自建项目选中该「项目」下拉；工作区卡片选中该「工作区」下拉），计数与筛选角标同步变化。
- **工作区绑定规则**（v2.7）：一个工作区同时只能绑定**一个未归档项目**——想给新项目绑已被占用的工作区，会提示冲突；先把旧项目归档（归档即让出绑定）或改其绑定即可。归档项目删除后，原属任务的历史里会出现「项目已删除，任务改为无项目（原项目：X）」，方便回溯。
- **多窗口编辑**（v2.7）：项目编辑带乐观锁。若同一项目在另一个窗口被改过，你这边保存时会提示「项目已被其他窗口修改」，弹窗内容会按最新数据刷新，确认后重存即可，不会静默覆盖。
- **新建/编辑成员**（v0.3；v0.5 弹窗简化）：页头右上「新建成员」或队长卡「编辑」。字段：名称（≤40，必填）、角色（负责人/管理员/成员/访客，人类权限标签）、队长（工作成员可换归属）、职位、成员状态（待命/工作中/受阻中）、人格（≤200，写这个成员的行事准则）、技能（逗号分隔，最多 8 个）、提供方、模型、联系方式。**成员类型不再是弹窗字段**：队长恒定唯一（由系统种子与守卫保证），新建的成员一律是工作成员。成员状态对工作成员通常由任务自动推导（有受阻任务→受阻中，有进行中或可开工的待办任务→工作中，只剩等前置的待办时显示待命），手工设置会被下一次刷新覆盖。
- **给成员选模型**（v0.4）：提供方/模型是下拉框，选项就是 DSH 里**已经配好的**模型目录，不用手打 id。默认停在「**继承工作区**」——意思是这个成员跟着宿主当前的默认模型走（弹窗下方会写出「跟随工作区默认模型 · provider/model」，让你知道现在继承的是哪个）。只有确实想让某个成员固定用别的模型时，才去点具体的 provider 与 model。以前填过的值如果已经从 DSH 里消失，下拉里会保留一项「`<id>`（当前值不在目录里）」并保持选中，不会被悄悄改掉。团队卡片副标题会显示 `provider/model` 或「继承工作区」。
- **删除**：成员与项目删除前有确认框；**队长卡与明细表中队长一行没有删除按钮**（服务端也直接拒绝删队长的请求）。任务在卡片菜单「删除任务」或编辑弹窗内删除。

## 数据与安全

- 数据全部本地存储，不联网。
- API 仅 DSH **owner** 身份可用（`connection.admit` 判定，非 owner 一律 403）。
- 状态文件损坏时自动备份为 `state.json.corrupt-<时间戳>` 并以空状态重启，不会卡死插件。
- 项目绑定的工作区若已从 DSH 中移除（工作目录被删/改名），插件启动时会自动解除该绑定并记一条警告日志；这类历史遗留值过去会显示成「不关联工作区」，v2.7 起在编辑弹窗里明确标为「（已失效）」。

## 已知边界（v0.5）

- 单用户本地模型：成员是「指派与协作对象」，不参与鉴权，不能登录；API 仅 DSH owner 可用。
- **真实 agent 会话需要宿主提供 `agents` 服务**。DSH 0.2.2 默认具备；缺失时插件不报错，进入降级：任务照常排队、成员标「会话不可用」，人工派单/汇报/验收仍可用。
- 会话权限固定为 `workspace-write`，cwd 是任务所属工作区的路径；**工具级 assignee 校验才是真正的权限边界**——成员工具只能读写自己的任务，越权调用直接拒绝。
- 会话生命周期跟随插件：插件卸载/停用会 dispose 所有会话；DSH 重启后懒恢复（先 resume 映射的 sessionId，失败则重建并补投简报）。重启时正在 `running` 的任务会重新排队，**不保证不重复投递**（简报可能收到两次，任务本身幂等）。
- 同一工作区串行执行；不同工作区可并行。成员被删除时其会话立即 dispose，任务回到「未指派」。
- 插件不主动读取完整会话日志做分析，只保留最近 80 条用于聊天抽屉展示；任务审计字段（`origin` / `sourceSessionId` / `agentSessionId`）只记录来源，不参与权限判断。
- 工作区发现依赖于 `$DSH_HOME/storages/workspace.json`：该文件不可读时插件不会校验也不会清理工作区绑定（宁可保留未知值也不误删数据）。
- 与 super-kanban 的差距：仍未实现项目「时间线/日程」子视图、工作区范围/活动时间范围切换、多面板形态（侧边栏/浮窗）、导出 JSON、AI 扫描与快聊。
